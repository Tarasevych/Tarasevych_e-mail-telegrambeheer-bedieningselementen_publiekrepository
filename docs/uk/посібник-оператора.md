# Посібник оператора

<!-- SID:preflight -->
## Попередня перевірка

Підтвердьте чинні повноваження етапу, наявність єдиного виконавця запису, незмінність зразка коду та визначену ціль повернення перед будь-якою зовнішньою дією. Тарифікація має залишатися свідомо закритою: не створюйте, не вмикайте повторно та не прив'язуйте платіжний рахунок.

## Середовище виконання

Локальний зразок спільного бота не є живим споживачем повідомлень. Його типові правила роботи: вхідний шлюз і друга версія вимкнені, аварійний вимикач увімкнений, тіньовий режим вимкнений, частка пробного запуску дорівнює `0`. Обмежений аналізатор отримує захищені посилання власника із серверних налаштувань після перевірки автентичності та не довіряє вхідним полям JSON від Telegram. Координатор повертає стан `ACK_SAFE` лише після повторостійкого запису в захищену скриньку вхідних і відповідної неподільної передачі стану під захисним бар'єром; стани `ROUTED` і `FAILED`, застарілий межовий лічильник та неоднозначний результат повертають `RETRY`. Зміна ключа доступу спільного бота, створення нового бота, виклики `setWebhook`, `deleteWebhook`, `getUpdates`, запуск або зупинка опитувача, зміна команд і меню та спостереження за поштою Gmail суворо заборонені до прямого приймального підтвердження власника для робочого середовища. Залежне від тарифікації розгортання Cloud Run, Pub/Sub і сховища таємних даних не виконується.

## Дії під час позаштатних подій

За наявності активного дубліката не підтверджуйте прийом як завершену дію: дочекайтеся закінчення строку оренди або штатного відновлення. Дублікат у стані `COMMITTED` є безпечним для підтвердження прийому лише тоді, коли відповідне надійне підтвердження передачі стану успішно пройшло контрольне вичитування; зафіксований стан без передачі стану є порушенням цілісності. У разі невідповідності автентифікації чи власника, суперечності тотожності або передачі стану чи неочікуваного маршруту залиште аварійний вимикач увімкненим, збережіть очищені докази кореляції та стану й поверніть основний маршрут на першу версію. Ніколи не повторюйте невідому зміну в живому середовищі. Ціллю повернення для робочого середовища залишається чинний споживач першої версії та незмінений ключ доступу спільного бота.
